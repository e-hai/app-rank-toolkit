方法：读代码 + 读线上 DOM + 用 Node 搭 DOM 桩实际执行四段脚本 + 边界值输入 + 全站内链扫描 + 单测

## 一、结论摘要

四个计算器「算得对」但「用得不顺」。核心问题集中在三处：

1. **结果只有一个数字，没有过程**。用户拿到 `Net: $3,143.70`，看不到下载量怎么折算、抽成扣了多少，无法自查，也无法说服别人。
2. **输入没有兜底**。金额留空会算成 `$0.00` 并当成正常结果输出；转化率填 150 没有任何提示；`收入估算` 的手续费下拉显示的是 `0.3 / 0.15` 这种裸小数。
3. **状态不落地**。所有输入只活在内存里，切语言、刷新、分享都会丢；语言切换是换 URL，于是「换语言后选中的地区变了」。

本轮已全部修掉，并顺带把单工具页体积从 104KB 压到 19KB（`DATA` 快照按工具裁剪）。剩余短板见第五节。

## 二、四个工具逐项评估

评分口径：功能正确性（公式与数据一致）、输入容错、结果可读性、状态与分享、可访问性。

| 工具 | 修正前评分 | 修正后 | 主要短板（修正前） |
|---|---|---|---|
| 排名变化 | 3/5 | 4.5/5 | 只输出一句自然语言，不显示区间倍数；0 或空值静默处理 |
| 收入估算 | 2.5/5 | 4.5/5 | 只有 gross/net 两个数，漏斗不可见；档位下拉显示裸小数 |
| 市场对比 | 2.5/5 | 4.5/5 | 只给重合数量与 app 名，没有两国排名，价值接近无 |
| 手续费 | 3/5 | 4.5/5 | 只有净额，没有抽成金额，也不便比较档位 |

### 2.1 排名变化

- 输入：原排名、现排名，默认 12 → 7
- 输出（修正后）：结论 + `排名区间倍数 0.25 → 0.45` + `曝光倍数 1.80×`
- 逻辑正确：`band()` 取 `RANK_BANDS` 的 ceiling 映射，1/3/10/20/30 五档，超出落 0.05 地板
- 边界：`0`、空值、负数都会命中 `invalid_input`，不再把 0 当成「第 0 名」

### 2.2 收入估算

- 漏斗：下载量 × 区间倍数 → 付费用户 = 下载 × 转化率 → 流水 = 付费 × 单价 → 抽成 → 到手
- 默认值实跑：50,000 下载、排名 8（0.45 倍）、转化 4%、单价 $4.99、标准档
  → 22,500 下载 / 900 付费 / 流水 $4,491 / 抽成 $1,347.30 / 到手 $3,143.70 / 单次下载收入 $0.20
- 修正后新增：`按排名区间折算后的下载量`、`付费用户`、`商店手续费`、`单次下载收入` 四行
- 已修 bug：手续费下拉原为 `<option value="standard">0.3</option>`，现为 `Standard 30%`

### 2.3 市场对比

- 输入：市场 A、市场 B、榜单（免费/畅销），默认 美区 vs 英区 免费榜
- 修正前：只返回「重合 5/10」+ 五个 app 名，用户无法判断差异
- 修正后：逐行给两国排名，例如 `ChatGPT #4 → #1`、`Vinted #3 → #7`，可直接看出「谁在本土更强」
- 数据面：快照里 6 个市场（us / gb / jp / kr / tr / tw）× 2 个榜单 × 前 10 名
- 容错：非法市场代码（如已下线的 `de`）回退默认；A 与 B 相同会提示「请选择两个不同的市场和一个榜单」，不再输出 10/10 的假重合

### 2.4 手续费计算器

- 输入：流水、档位，默认 $10,000 标准档
- 修正后：`流水 $10,000` / `抽成 $3,000` / `到手 $7,000`，并附「同一流水在各档位下的对比」：标准 30% → $7,000，小型计划 15% → $8,500
- 价值点在于「同一笔钱在两个档位差多少」，这是原来完全没有信息

## 三、已修问题清单

| # | 问题 | 影响 | 处理 |
|---|---|---|---|
| 1 | 结果仅一行自然语言 | 无法自查，可信度低 | 改为「结论 + 明细表」 |
| 2 | 空金额算出 `$0.00` 并当正常结果 | 误导 | `val()` 把空串判为 NaN，落 `invalid_input` |
| 3 | 转化率 150 无提示 | 结果荒谬 | 校验 0–100，超界报错 |
| 4 | 档位下拉显示 `0.3 / 0.15` | 看不懂 | 改用 `Standard 30% / Small program 15%` |
| 5 | 无重置 | 试错成本高 | 加 `type=reset`，重置即重算 |
| 6 | 输入只活在内存 | 切语言/刷新/分享即丢 | 参数写入 URL query；语言切换链接带上当前 query |
| 7 | 结果区无播报 | 读屏用户拿不到结果 | `role="status" aria-live="polite"` |
| 8 | label 未绑定输入 | 点标签不聚焦 | 补 `for` / `id` |
| 9 | 无 JS 时空白 | 公式不可见 | `<noscript>` 提示并指向方法页 |
| 10 | 每个工具页内嵌 85KB 全量快照 | 首屏慢、流量浪费 | 仅市场对比需要数据，且只留 `rank/name/app_id`；其余页 `const DATA={}` |
| 11 | 结果页无公式入口 | 想核公式要自己找 | 结果下方加方法页链接（按语言前缀） |
| 12 | 工具页之间无互链 | 用完即走 | 底部互链另外 3 个工具 + 指南 + 市场 + 榜单 |

## 四、验证记录

- **脚本实跑**：用 Node + DOM 桩执行四段脚本，默认值输出、URL 还原、边界值三条路径全部命中预期

- **线上核验**：`aria-live`、重置按钮、`noscript`、明细表、中文档位对比文案均已在 `apprank-toolkit.pages.dev` 生效

## 五、仍存在的短板（按优先级）

1. **没有真实浏览器端到端测试**。当前验证是「生成 HTML 加 Node 桩」，覆盖不到真实 CSS 布局、移动端键盘、Safari 的 `Intl` 差异。建议接 Playwright 跑三条冒烟：默认值、切换市场、非法输入。
2. **跨语言数值格式未本地化**。金额统一 `en-US` 格式（`$1,234.56`），土耳其、日本用户看到的是美元符号加英文逗号。若要做本地化，需给 `money()` 传入 locale，但要注意货币本身仍是美元，只改分隔符不改币种。
3. **市场对比只支持一对市场**。目前是「A vs B」，无法一次看「六市场 × 两榜」的重合矩阵；这是下一步最值得做的功能扩展。
4. **没有历史对比**。工具用的是当日快照，无法回答「上周第 8、这周第 3，涨了几位」之外的时序问题；趋势页（`/apps/...`）有 30 天曲线但被 noindex，工具与趋势页之间没有互相引用。
5. **没有输入示例预设**。新手不知道该填 50,000 还是 500；建议加「小团队 / 中型 / 头部」三个预设按钮。
6. **无埋点**。不知道用户最常改哪个字段、在哪一步放弃；可用 Cloudflare Web Analytics 做无 cookie 统计，先看四个工具页的跳出率。

---

## 六、下一步建议（按性价比排序）

1. 市场对比扩成「六市场 × 免费/畅销」重合矩阵（一张表，两条轴），一次看完全部差异
2. 三个预设档位按钮（小团队 5k 下载 / 中型 50k / 头部 500k），降低首次使用门槛
3. Playwright 冒烟测试三条，锁住本轮修好的行为
4. 数值格式按语言本地化（仅分隔符，币种仍 USD）
5. 接 Cloudflare Web Analytics，先有数据再谈下一轮改版
